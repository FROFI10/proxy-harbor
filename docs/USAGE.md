# Proxy Harbor

Локальный сервис, который собирает публичные прокси, удаляет дубли, проверяет их реальным HTTP/HTTPS-запросом, сохраняет результаты в SQLite и выдаёт **только свежие рабочие адреса** другим программам через HTTP API. Управление — через русскоязычный web UI в тёмном стиле.

> **Важно:** бесплатные публичные прокси недоверенные и нестабильные. Не передавайте через них пароли, платёжные данные, токены или конфиденциальную информацию. Положительный тест означает работоспособность в момент проверки, а не безопасность владельца прокси или гарантию будущей доступности.

## 1. Где находится программа

После клонирования исходники находятся в папке проекта:

```text
proxy-harbor
```

По умолчанию:

- **Web UI:** http://127.0.0.1:8765/
- **Один прокси:** http://127.0.0.1:8765/api/proxy
- **Интерактивная документация API:** http://127.0.0.1:8765/docs
- **OpenAPI JSON:** http://127.0.0.1:8765/openapi.json
- **Проверка сервиса:** http://127.0.0.1:8765/health

Все пути к данным вычисляются относительно папки программы, **а не текущей папки терминала**. Пути с пробелами поддерживаются. Папку можно перенести, но после переноса на другую машину или замены Python лучше пересоздать `.venv` через `setup.bat`.

## 2. Требования и быстрый запуск

Основной вариант — Windows x64, Python **3.11 или новее**, доступ в Интернет для первоначальной установки, загрузки списков и проверки прокси. Node.js, Docker, PostgreSQL и отдельный web-сервер для обычной работы **не нужны**. Интерфейс, шрифты и Swagger UI обслуживаются локально, без CDN.

### Самый простой способ

Дважды нажмите **`start.bat`** в папке проекта.

- Если окружения ещё нет, скрипт вызовет `setup.bat` и установит зависимости в `.venv`.
- Затем запустит сервис и откроет браузер **после готовности сервера**.
- Окно консоли должно оставаться открытым: в нём работает процесс сервиса.
- По умолчанию автоматический первый сбор начинается после запуска приложения.
- Первая выдача станет доступна после появления успешно проверенных прокси. До этого API вернёт понятный ответ **503**, а не случайный непроверенный адрес.

### Из PowerShell

```powershell
Set-Location '.\proxy-harbor'
.\start.bat
```

Только установить зависимости:

```powershell
.\setup.bat
```

Без автоматического открытия браузера:

```powershell
.\.venv\Scripts\python.exe run.py
```

Другой порт:

```powershell
.\.venv\Scripts\python.exe run.py --port 9876 --open-browser
```

Тогда интерфейс и API будут на `http://127.0.0.1:9876`, а не на `8765`.

Запуск без автоматического сбора **только на текущий запуск**:

```powershell
.\.venv\Scripts\python.exe run.py --no-auto --open-browser
```

Версия и справка:

```powershell
.\.venv\Scripts\python.exe run.py --version
.\.venv\Scripts\python.exe run.py --help
```

`--no-auto` не переписывает сохранённую настройку `auto_collect`. Чтобы отключить автоматические циклы постоянно, измените её в разделе «Настройки».

### Linux/macOS

Исходный код рассчитан на Python и использует кроссплатформенную блокировку экземпляра. Для запуска из bash есть `start.sh`:

```bash
bash start.sh --open-browser
```

Тестирование выполнено на Windows; работу на другой ОС следует дополнительно проверить в её окружении.

## 3. Что делает сервис

Поток обработки:

```text
Публичные feeds / ручной импорт
           ↓
Параллельная загрузка с таймаутами и ограничением размера
           ↓
Разбор TXT / HTML / JSON / CSV
           ↓
Проверка IP и порта → удаление дублей → SQLite (pending)
           ↓
Быстрая TCP-проверка → реальный запрос через HTTP/SOCKS
           ↓
Отдельная HTTPS-проверка с проверкой сертификата
           ↓
SQLite: alive / dead + задержка, exit IP, время проверки
           ↓
Локальный API: только alive и только в пределах freshness
```

### Протоколы

- **HTTP:** обычный forward proxy; при успешной HTTPS-проверке — также HTTP CONNECT.
- **SOCKS4:** проверка через настоящий SOCKS-туннель; для доменного имени используется удалённое DNS-разрешение.
- **SOCKS5:** проверка SOCKS5 с удалённым DNS-разрешением.
- IPv4 и корректные IPv6-литералы; IPv6 в URL заключён в квадратные скобки.

**HTTPS в списках — не отдельный четвёртый тип прокси.** Такой список нормализуется к HTTP. Признак `supports_https=true` выставляется только после успешного HTTPS-запроса через прокси с включённой TLS-проверкой. Даже для HTTPS-сайта адрес HTTP-прокси обычно остаётся вида `http://IP:PORT`, не `https://IP:PORT`.

### Дедупликация

Уникальность задаётся тройкой **протокол + нормализованный IP + порт** и защищена индексом SQLite. Один endpoint, найденный в нескольких feeds, хранится одной записью для соответствующего протокола, с сохранением происхождения. Один IP:port для разных протоколов проверяется раздельно: поддержка HTTP не доказывает поддержку SOCKS5.

### Что считается рабочим

Недостаточно открытого TCP-порта. Проверка должна:

1. Установить соединение с самим прокси за ограниченное время.
2. Выполнить запрос **через прокси**, без прямого fallback и без использования системного `HTTP_PROXY`.
3. Получить корректный ответ IP-endpoint и публичный exit IP.
4. На **другом Host** получить ответ echo-endpoint с новым случайным nonce и публичным `origin`. Одна и та же пара IP-probe + challenge должна пройти для HTTP либо для HTTPS.
5. Для HTTPS — пройти проверку TLS-сертификатов обоих конечных серверов; отключения проверки сертификата нет.

По умолчанию независимый challenge — `http://httpbingo.org/anything?nonce=...` и HTTPS-вариант. Если настроенный probe уже использует `httpbingo.org`, выбирается `httpbin.org`. Ответ одного IP-endpoint недостаточен: CDN/reverse endpoint может отвечать только для одного Host и не быть универсальным прокси. Nonce препятствует повторному использованию кешированного ответа.

Если HTTP-тест не прошёл, но HTTPS-тест прошёл, HTTPS-capable прокси не теряется. Если HTTPS не прошёл, но HTTP прошёл, адрес может быть рабочим для HTTP, однако не попадёт в выдачу с `https_only=true`.

По умолчанию IP-probe адреса — `http://api.ipify.org?format=json` и `https://api.ipify.org?format=json`; независимо от них выполняется challenge на другом Host. IP-probe можно заменить публичными HTTP/HTTPS endpoint, возвращающими JSON с `ip` либо `origin`. Произвольная HTML-страница вместо IP-endpoint для этой проверки не подходит.

### Состояния базы

- **pending** — обнаружен, полноценная проверка ещё не выполнена.
- **alive** — последняя полноценная проверка успешна.
- **dead** — последняя проверка неуспешна либо клиент сообщил о неработоспособности.
- **stale** — запись была alive, но время проверки вышло за `freshness`. Это вычисляемая категория свежести, а не основание выдавать старый адрес.

В базе есть и кандидаты, и результаты неуспешных проверок — это позволяет не терять историю и не проверять один и тот же дубль заново при каждом feed. Но **API выдачи не отдаёт pending, dead или stale**.

Для успешной выдачи нужна **валидация V2** и корректная внутренняя отметка проверки. При обновлении старые weak-alive переводятся обратно в `pending`; простое обновление их timestamp старым writer не делает их доверенными. `report ok=true` эту защиту не обходит.

## 4. Источники: количество, добавление и обновление

Стартовый каталог — **`sources.json`**. Подробный перечень, число feeds и независимых издателей, результаты реальных загрузок и ограничения приведены в:

- `docs/SOURCES.md`;
- `docs/source-audit.json`.

Один издатель может публиковать несколько списков разных протоколов. Поэтому число feeds не равно числу независимых издателей, а зеркала часто содержат одни и те же адреса.

«Максимум источников» реализован как большой расширяемый каталог, а не обещание собрать весь Интернет. Закрытые сайты, логины, paywall, CAPTCHA и заблокированные API автоматически не обходятся. Ошибки HTTP, DNS, таймауты и пустые списки видны в UI; остальные источники продолжают обрабатываться.

### Разница между двумя файлами каталога

- **`sources.json` в корне** — первоначальный проверенный каталог поставки.
- **`data/sources.json`** — рабочий каталог после изменений через UI/API. Имеет приоритет при следующих запусках.

Так обновление исходного каталога не вернёт удалённые пользователем источники и не отменит его переключатели. Если хотите вернуться к стартовому каталогу, остановите сервис и **сначала сохраните резервную копию** `data/sources.json`, затем уберите этот рабочий файл. Следующий запуск использует корневой `sources.json`.

### Через интерфейс

Вкладка «Источники» позволяет:

- добавить публичный URL и указать протокол/формат;
- включить или отключить feed;
- удалить feed из рабочего каталога;
- посмотреть время загрузки, число найденных/новых адресов и причину ошибки;
- запустить ограниченный поиск дополнительных списков в GitHub.

Добавленный вручную URL ещё **не считается проверенным здоровым feed**: его фактический результат появится после загрузки. Настройки источника влияют на следующие циклы; текущая загрузка уже взятого в работу источника может закончиться. Удаление источника не удаляет автоматически ранее проверенные прокси — они продолжают жить по собственным результатам и freshness.

### GitHub discovery

Это дополнение к фиксированному каталогу, а не бесконечное сканирование. Поиск ограничен числом репозиториев/файлов, проверяет содержимое предложенных feeds и пропускает дубли. Используется публичный GitHub API без обязательного токена. При rate limit или отказе доступа сервис сообщает ошибку, не придумывает новые источники. Повторять поиск каждую секунду не нужно.

Для источников запрещены учётные данные в URL, локальные/частные IP, неоднозначные числовые адреса и неподдерживаемые схемы. DNS и каждый redirect проверяются; размер распакованного ответа ограничен.

## 5. Как другая программа получает прокси

**Это API выдачи адресов, а не forward proxy на порту 8765.** Нельзя настроить браузер использовать `127.0.0.1:8765` как HTTP/SOCKS-прокси. Сначала программа запрашивает адрес через API, затем сама подключается к полученному upstream-прокси.

### Один адрес в JSON

```powershell
curl.exe --fail "http://127.0.0.1:8765/api/proxy"
```

Ответ — объект записи прокси. Основные поля:

| Поле | Значение |
|---|---|
| `id` | идентификатор записи; нужен для `/report` |
| `proxy`, `url` | одинаковый URL `protocol://IP:PORT` |
| `address` | только `IP:PORT`; для IPv6 — `[IP]:PORT` |
| `host`, `port` | IP и числовой порт раздельно |
| `protocol` | `http`, `socks4` или `socks5` |
| `status` | при выдаче — `alive` |
| `latency_ms` | измеренная задержка в миллисекундах |
| `supports_https` | успешность отдельной HTTPS-проверки |
| `exit_ip` | IP выхода из проверочного ответа |
| `last_checked` | Unix timestamp последней проверки |
| `successes`, `failures` | счётчики результатов проверок |
| `requests` | число выдач этой записи через API |
| `source_count` | число сохранённых источников происхождения |
| `validation_version` | при выдаче — `2`, полноценная независимая проверка |

Дополнительные поля времени первого/последнего обнаружения могут быть полезны для диагностики. Время в API/SQLite — Unix timestamp в секундах, UTC; UI форматирует его для отображения.

### URL обычным текстом

```powershell
curl.exe --fail "http://127.0.0.1:8765/api/proxy?format=text"
```

Возвращается **одна строка с URL и переводом строки**, без JSON и кавычек. Подходит программам, которые ожидают `http://IP:PORT` или `socks5://IP:PORT`.

### Только IP:port

```powershell
curl.exe --fail "http://127.0.0.1:8765/api/proxy?protocol=http&format=address"
```

В этом формате протокол не записан в самой строке. Его должен знать клиент — поэтому желательно указывать фильтр `protocol`.

### Самый быстрый HTTP-прокси с работающим HTTPS

```powershell
curl.exe --fail "http://127.0.0.1:8765/api/proxy?protocol=http&https_only=true&strategy=best&max_latency_ms=1500&format=text"
```

### Параметры `/api/proxy`

| Параметр | Значения / назначение |
|---|---|
| `protocol` | необязательный: `http`, `socks4`, `socks5` |
| `https_only` | `true` — только адреса с прошедшим HTTPS-тестом |
| `max_latency_ms` | необязательный положительный верхний предел задержки; до 60000 |
| `strategy` | `random` по умолчанию; также `best`, `round_robin` |
| `format` | `json` по умолчанию; `text` — URL; `address` — IP:port |

- **random** — случайный подходящий адрес.
- **best** — подходящий адрес с наименьшей задержкой.
- **round_robin** — ротация по выдачам, чтобы распределять использование адресов.

Выдача увеличивает счётчик использования. Это **не аренда** и не эксклюзивная блокировка прокси: другой клиент тоже может получить тот же адрес. Если нужен стабильный IP в течение сессии, клиент должен сохранить полученный адрес и сам управлять его повторным использованием/заменой.

### Несколько адресов за запрос

```powershell
curl.exe --fail "http://127.0.0.1:8765/api/proxies/batch?count=10&protocol=socks5&https_only=true"
```

JSON содержит `items`, `count` и `requested`. Если доступно меньше, чем запрошено, `count` честно показывает фактическое число. Если нет ни одного подходящего адреса — **503**. `count` в запросе допустим от 1 до 1000. Поддерживаются те же фильтры и стратегии, `format=text`/`address` дают по одному адресу на строку.

### Если рабочих прокси нет

Ответ: HTTP **503**, JSON с объяснением в `detail`, заголовок `Retry-After: 15`.

Это нормальное состояние при первом старте, после истечения freshness или при слишком строгих фильтрах. Запустите сбор/проверку, ослабьте фильтр задержки либо повторите запрос позже с паузой. Не устраивайте busy loop без задержки и не используйте непроверенные адреса как fallback.

## 6. Пример клиента на Python

Для этой **клиентской** программы отдельно установите `requests` в её собственное окружение:

```powershell
python -m pip install requests
```

Получить HTTP-прокси, использовать его и сообщить о сетевой ошибке:

```python
import requests

API = "http://127.0.0.1:8765"
client = requests.Session()
client.trust_env = False

selected = client.get(
    f"{API}/api/proxy",
    params={"protocol": "http", "https_only": "true", "strategy": "round_robin"},
    timeout=10,
)
if selected.status_code == 503:
    raise SystemExit("Нет готовых прокси: запустите сбор и повторите позднее")
selected.raise_for_status()
record = selected.json()
proxy_url = record["url"]

try:
    response = client.get(
        "https://example.com/",  # замените на нужный вам разрешённый URL
        proxies={"http": proxy_url, "https": proxy_url},
        timeout=(5, 15),
        verify=True,
    )
    print(response.status_code)
except requests.RequestException:
    try:
        client.post(
            f"{API}/api/proxies/{record['id']}/report",
            json={"ok": False},
            timeout=5,
        )
    except requests.RequestException:
        pass
    raise
```

Ответ сайта 401/404/503 сам по себе не доказывает поломку прокси: не помечайте адрес нерабочим только из-за прикладного HTTP-статуса сайта.

Для SOCKS в `requests` нужен `requests[socks]`. Если хотите DNS на стороне SOCKS5-прокси, у `requests` используется клиентская схема `socks5h://`: явно адаптируйте полученный `socks5://` URL под библиотеку. В сервисе при собственной проверке SOCKS удалённое DNS уже включено. Схема, которую ожидает конкретная клиентская библиотека, может отличаться от канонической схемы API.

В любой другой программе алгоритм тот же: **GET → разобрать JSON или текст → настроить upstream proxy в своей HTTP-библиотеке → при сетевой ошибке запросить другой адрес**.

## 7. Список, поиск и экспорт

### Просмотр базы

```powershell
curl.exe "http://127.0.0.1:8765/api/proxies?status=alive&protocol=http&sort=latency&limit=50&offset=0"
```

Ответ: `items`, `total`, `limit`, `offset`. `total` — число записей, подходящих текущим фильтрам, а не число строк текущей страницы.

- `status`: `alive` по умолчанию; также `pending`, `dead`, `all`.
- `sort`: `latency`, `recent`, `requests`.
- `query`: поиск по адресу/IP/порту/URL, до 120 символов.
- `limit`: от 1 до 500; `offset` — неотрицательный.
- `protocol`, `https_only`, `max_latency_ms` — как при выдаче.

`status=alive` исключает устаревшие проверки. В `status=all` старые записи остаются доступны для диагностики, а UI отличает их от свежих.

### Экспорт только свежих рабочих адресов

```powershell
curl.exe --fail "http://127.0.0.1:8765/api/proxies/export?protocol=http&https_only=true&format=text&limit=1000" --output proxies.txt
```

`format=json` экспортирует записи, `format=text` — URL по одному на строку, `format=address` — IP:port. Максимальный `limit` экспорта — 10000. Экспорт и просмотр списка **не увеличивают счётчики выдачи**, в отличие от `/api/proxy` и `/api/proxies/batch`.

## 8. Управление через API

| Метод и путь | Назначение |
|---|---|
| `GET /health` | жив ли сам web-сервис; не означает наличие прокси |
| `GET /api/stats` | база, протоколы, свежесть, счётчики, прогресс и журнал |
| `POST /api/collect` | загрузить источники и проверить очередь |
| `POST /api/recheck` | проверять существующие адреса без новой загрузки feeds |
| `POST /api/stop` | безопасно остановить текущий цикл |
| `GET /api/runs` | последние циклы; `total` здесь — число возвращённых строк |
| `GET /api/sources` | текущий рабочий каталог с результатами загрузок |
| `POST /api/sources` | добавить feed |
| `PATCH /api/sources/{id}` | включить/отключить: `{"enabled": false}` |
| `DELETE /api/sources/{id}` | удалить feed из рабочего каталога |
| `POST /api/sources/discover` | ограниченный поиск новых GitHub feeds |
| `POST /api/import` | импорт публичных кандидатов, пока не alive |
| `POST /api/proxies/{id}/report` | клиентский результат: `{"ok": false}` |
| `GET /api/settings` | текущие настройки |
| `PATCH /api/settings` | изменить и сохранить часть настроек |

Примеры без тела:

```powershell
curl.exe -X POST "http://127.0.0.1:8765/api/collect"
curl.exe -X POST "http://127.0.0.1:8765/api/recheck"
curl.exe -X POST "http://127.0.0.1:8765/api/stop"
```

Параллельный второй цикл не создаётся. Если цикл уже идёт, `started=false` с пояснением, а не ещё одна очередь из десятков тысяч запросов.

### Ручной импорт

В UI есть форма импорта. API принимает объект `text` + `protocol`:

```powershell
$body = @{
    text = (Get-Content '.\my-proxies.txt' -Raw)
    protocol = 'http'
} | ConvertTo-Json
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/api/import' -Method Post -ContentType 'application/json' -Body $body
```

Ответ показывает число корректно разобранных уникальных кандидатов (`parsed`) и новых записей в базе (`added`). Неподходящие IP/порты отбрасываются. Сам импорт **не доказывает работоспособность**: нажмите «Проверить» или дождитесь автоматического цикла.

### Сообщить о неисправном адресе

```powershell
# Замените 123 фактическим id, полученным при выдаче.
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/api/proxies/123/report' -Method Post -ContentType 'application/json' -Body '{"ok":false}'
```

Неуспешный отчёт исключает адрес из выдачи. `ok=true` не подменяет полноценную проверку и не делает старую/непроверенную запись свежей.

### Добавить свой feed

```powershell
$url = Read-Host 'Введите реальный публичный URL списка прокси'
$body = @{
    name = 'Мой источник'
    url = $url
    protocol = 'http'
    format = 'text'
    enabled = $true
} | ConvertTo-Json
Invoke-RestMethod -Uri 'http://127.0.0.1:8765/api/sources' -Method Post -ContentType 'application/json' -Body $body
```

Для JSON/HTML/CSV выберите соответствующий `format`; для SOCKS — соответствующий `protocol`. Одинаковый URL + протокол повторно не добавляется: ответ 409.

### Типовые ошибки

- **404:** неизвестная запись/источник.
- **409:** дубль feed или уже выполняющийся discovery.
- **413:** тело запроса больше 2 МБ.
- **422:** неверные параметры, приватный/неоднозначный URL, недопустимые настройки или отсутствие корректных кандидатов при импорте.
- **503:** нет свежего подходящего рабочего прокси.
- **502/504 при discovery:** ошибка GitHub/лимит доступа либо превышен общий таймаут поиска; каталог не наполняется выдуманными результатами.

## 9. Настройки скорости и свежести

Настройки сохраняются в **`config.json`**. При отсутствии файла используются безопасные значения по умолчанию; launcher создаёт файл при первом запуске. Некорректный существующий файл не переписывается молча — исправьте его либо восстановите резервную копию.

| Настройка | По умолчанию | Назначение |
|---|---:|---|
| `auto_collect` | `true` | автоматические сбор/повторные проверки |
| `collect_interval` | 900 | пауза между завершённым сбором и следующим сбором, секунд |
| `check_concurrency` | 120 | максимальное число параллельно проверяемых прокси |
| `source_concurrency` | 10 | одновременные загрузки feeds |
| `check_timeout` | 4.0 | таймаут полноценного проверочного запроса, секунд |
| `connect_timeout` | 1.5 | короткий таймаут соединения/TCP-проверки, секунд |
| `source_timeout` | 15.0 | общий таймаут загрузки одного feed, секунд |
| `max_per_cycle` | 20000 | верхняя граница числа проверок за один цикл |
| `max_candidates` | 100000 | ограничение уникальных кандидатов, принимаемых из feeds в цикл |
| `recheck_interval` | 600 | интервал повторной проверки, секунд |
| `freshness` | 600 | максимальный возраст успешной проверки для API, секунд |
| `retention_days` | 3 | срок хранения старых неактуальных записей при очистке |
| `http_probe_url` | `http://api.ipify.org?format=json` | HTTP IP-endpoint |
| `https_probe_url` | `https://api.ipify.org?format=json` | HTTPS IP-endpoint |

Границы валидируются: concurrency проверок 1–400, feeds 1–24, интервалы/freshness 60–86400 секунд, timeout проверки 1–30 секунд, connect timeout 0.2–5 секунд, source timeout 5–60 секунд, проверки за цикл 1–100000, кандидаты 1000–500000, retention 1–30 дней.

**Почему есть лимиты:** большой каталог может содержать сотни тысяч дублей и нерабочих адресов. Создать все соединения одновременно — способ исчерпать сокеты/память, а не ускорить полезную проверку. Используются ограниченные worker queues и пакетные записи результатов в SQLite. Остальная очередь не пропадает и может проверяться в последующих циклах.

Практически:

- слабый ПК/канал: уменьшите concurrency примерно до 40–80;
- достаточно ресурсов: 120 — стартовый баланс, повышайте постепенно;
- слишком короткий timeout отбрасывает медленные, но рабочие прокси;
- слишком большой freshness позволяет дольше использовать старые результаты — скорость ответа это не заменяет свежестью;
- если feeds/probe endpoint временно недоступны, сначала посмотрите ошибки, а не просто увеличивайте все лимиты;
- HTTP 429/отказ проверочного provider может дать ложное отрицание: «не подтвердился тест» не всегда означает закрытый TCP-порт. Безопасная выдача при этом не возвращается к одиночной слабой проверке;
- HTTPS нужен — используйте `https_only=true`. Рабочий HTTP-прокси без CONNECT не подходит для HTTPS, а самоподписанная цепочка сертификатов не принимается.

Web UI сохраняет валидированные настройки через API. Настройки проверки используются со следующего цикла; фильтр freshness выдачи применяется к текущим запросам сразу. `POST /api/stop` останавливает **только текущий цикл**: при включённом `auto_collect` таймеры продолжают действовать. Для полного отключения автоматического сбора сохраните `auto_collect=false`.

## 10. Как пользоваться интерфейсом

- **Обзор:** реальное число рабочих/ожидающих/устаревших прокси, протоколы, ход цикла, очередь и события.
- **Прокси:** поиск, фильтры, сортировка, страницы, копирование URL, экспорт, импорт и работа с результатами проверки.
- **Источники:** каталог, статусы загрузок, добавление, переключатели, удаление и discovery.
- **API:** конструктор/примеры запроса, копирование и тестирование ответа сервиса.
- **Настройки:** сохранение параметров скорости, расписания и проверки.

Интерфейс опрашивает сервис, не рисует придуманные показатели. До поступления данных показываются пустые/ожидающие состояния; ошибки связи видны отдельно. География и анонимность не угадываются по IP: такие сведения без отдельной проверки не заявляются.

```text
proxy-harbor/

├── setup.bat               # установка только в .venv

├── requirements-dev.txt    # pytest, браузерные тесты, lint
├── config.json             # рабочие настройки (создаётся/обновляется локально)
├── sources.json            # исходный каталог поставки
├── README.md
├── proxyharbor/
│   ├── app.py              # FastAPI routes, web UI и документация
│   ├── config.py           # строгая валидация, атомарное сохранение
│   ├── service.py          # циклы, расписание, ограниченные workers, прогресс
│   ├── models.py           # типы ProxyCandidate / CheckResult / SourceSpec
│   ├── parsing.py          # разбор форматов, нормализация, фильтрация
│   ├── checker.py          # TCP + HTTP/SOCKS + отдельный TLS-тест
│   ├── storage.py          # асинхронная SQLite, индексы, provenance, выдача
│   ├── security.py         # loopback, Host/origin и размер запроса
│   ├── instance.py         # системная блокировка второго экземпляра
│   └── static/             # HTML/CSS/JS, локальные Swagger assets

│   ├── proxies.sqlite3     # база данных
│   ├── sources.json        # изменённый пользователем рабочий каталог
```

SQLite используется в WAL-режиме, с уникальными индексами и параметризованными запросами. Работа БД не должна блокировать event loop; результаты пишутся пакетами. При активном WAL могут существовать файлы `proxies.sqlite3-wal` и `proxies.sqlite3-shm`: это нормально.


## 12. Остановка, резервная копия, повторный запуск

- Остановить текущий сбор: кнопка «Остановить» или `POST /api/stop`.
- Завершить сам сервер: **Ctrl+C** в его консоли. Дождитесь закрытия процесса перед копированием/перемещением базы.
- Повторный запуск: `start.bat`; база и настройки сохраняются.
- Второй экземпляр из той же папки не запускается — защищает базу и расписание от параллельных сборщиков.

Для простой резервной копии **при остановленном сервисе** сохраните:

1. `data/proxies.sqlite3`;
2. `data/sources.json`, если есть;
3. `config.json`;
4. при необходимости журналы и аудит.

Не копируйте только основной `.sqlite3` файл во время активной WAL-записи: последние изменения могут находиться в `-wal`. Для online backup используйте штатный SQLite backup API, либо сначала корректно остановите сервис.

Наличие `data/service.lock` после завершения не мешает запуску. Блокировка принадлежит ОС и освобождается при закрытии процесса; удалять файл для «сброса» работающего экземпляра не нужно.

## 13. Безопасность и ограничения

- API слушает loopback. CLI не разрешает `0.0.0.0`; не публикуйте порт в Интернет.
- Есть ограничения Host и origin для защиты от DNS rebinding/cross-site запросов. CORS не открыт всем сайтам.
- **Loopback не заменяет аутентификацию:** любой локальный процесс с доступом к этому компьютеру потенциально может вызвать API. Не запускайте сервис на недоверенной многопользовательской машине как защищённую административную панель.
- Источники и прокси не могут направлять проверки на localhost/частные сети через свой endpoint; источники проверяются также по DNS и redirect.
- Входы валидируются, SQL параметризован, непроверенные строки не вставляются в HTML как исполняемый код.
- TLS verification не отключается для публичных HTTPS-проверок.
- Прокси с логином/паролем и hostname вместо IP не поддерживаются этим публичным пулом.
- Число запросов, размер тела и очереди ограничены, но исходящие проверки всё равно создают заметный TCP/HTTP-трафик. Используйте программу там, где это разрешено правилами сети и источников.
- Нет гарантии анонимности, эксклюзивного использования, страны, скорости или постоянного наличия бесплатных прокси.
- Это не VPN, не браузерный fingerprint-сервис, не TLS MITM и не средство обхода авторизации сайтов.

## 14. Если что-то не работает

### API возвращает 503

Откройте «Обзор»: есть ли проверенные свежие alive? Дождитесь первой проверки, проверьте `https_only`/`protocol`/`max_latency_ms`, запустите повторную проверку. Нулевой рабочий пул честно остаётся нулевым: сервис не подменяет его демонстрационными данными.

### Источники дают ошибки

Посмотрите `last_error` в «Источники» и журнал. Возможны удалённый файл, HTTP 403/429/5xx, DNS, timeout, слишком большой/пустой ответ. Отключите неактуальный URL или замените его. Ошибка одного feed не должна останавливать остальные.

### Порт занят / второй экземпляр

Закройте уже работающий Proxy Harbor либо выберите другой порт **после остановки экземпляра из этой папки**. Не удаляйте lock-файл работающего процесса. Если другой процесс занимает только порт, используйте `run.py --port 9876`.

### Python или зависимости не найдены

Установите Python x64 3.11+, проверьте его запуск, затем `setup.bat`. Установка требует доступ к PyPI. Не меняйте ExecutionPolicy PowerShell ради `.bat`: это не PowerShell-скрипт.

### Конфигурация не проходит проверку

Проверьте JSON, числовые границы, строгие boolean (`true`/`false`) и public HTTP/HTTPS probe URL. Существующий некорректный файл не исправляется молча. Перед заменой сохраните копию.

### Браузер не открылся автоматически

Вручную откройте адрес, который напечатан в консоли. `--open-browser` зависит от системного обработчика браузера; работа HTTP-сервиса от него не зависит.

## 15. Тесты и проверка разработки

Developer-зависимости не нужны для обычного использования. Для воспроизведения тестов:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check proxyharbor tests run.py
```

Если установлен Node.js, дополнительная синтаксическая проверка web JavaScript:

```powershell
node --check proxyharbor/static/app.js
```

Автотесты используют изолированные базы и контролируемые HTTP/SOCKS/TLS-серверы; тестовые адреса/ответы не добавляются в рабочую базу. Браузерные тесты проверяют интерфейс на отдельном контролируемом API. Это воспроизводимые тесты функций, не утверждение о постоянной доступности конкретного бесплатного публичного прокси. Для фактического состояния смотрите живой сервис и аудит/отчёт реального запуска.
